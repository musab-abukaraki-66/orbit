# Orbit — Agent Guide

## What this project is

**Orbit** is an early-stage web application scaffolded with `create-next-app`. It is a single Next.js app (not a monorepo) with one route (`/`) and default boilerplate UI. All application code and config live in this directory (the directory containing `package.json`).

## Tech stack

| Tool | Version |
|------|---------|
| Next.js | 16.3.0 |
| React | 19.2.8 |
| React DOM | 19.2.8 |
| TypeScript | ^5 |
| Tailwind CSS | ^4 |
| ESLint | ^9 (`eslint-config-next` 16.3.0) |
| Node types | ^20 |

**Also used:** Geist + Geist Mono fonts via `next/font/google`, PostCSS with `@tailwindcss/postcss`.

## Development server

From the project root:

```bash
npm install    # first time only
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Edit `app/page.tsx` for hot-reloaded changes.

Production:

```bash
npm run build
npm run start
```

## Coding conventions

- **Language:** TypeScript with `strict: true`. Prefer `.tsx` for components.
- **Imports:** Use the `@/` path alias (maps to project root), e.g. `@/app/components/Button`.
- **Components:** Default-export React function components. Use named exports for utilities/types when sharing across files.
- **Styling:** Tailwind utility classes in JSX; shared tokens in `app/globals.css`.
- **Images:** Use `next/image` for optimized images; static files go in `public/`.
- **Metadata:** Export `metadata` or `generateMetadata` from layout/page files (see `app/layout.tsx`).
- **Scope:** Make minimal, focused changes. Match existing patterns before introducing new abstractions.
- **Lint:** Run `npm run lint` after substantive edits.

## Important development rules

1. **Next.js 16 differs from older versions.** APIs, conventions, and file structure may not match training data. Before writing Next.js code, read guides in `node_modules/next/dist/docs/` (relative to this directory). Heed deprecation notices.
2. **Do not edit** `next-env.d.ts` — it is managed by Next.js.
3. **`AGENTS.md` is auto-generated** by `next dev`. Do not delete it from diffs expecting it to stay gone; commit it with your work to keep the tree clean.
4. **Do not commit secrets** (`.env.local`, API keys, credentials).
5. **Only create commits or PRs when explicitly asked.**
6. **`next.config.ts`** is the place for Next.js options (redirects, images, env, etc.) — not inline hacks in components.

## Next.js App Router conventions

- **Routing is filesystem-based** under `app/`:
  - `app/page.tsx` → `/`
  - `app/about/page.tsx` → `/about`
  - `app/blog/[slug]/page.tsx` → dynamic segment
- **`layout.tsx`** wraps nested routes; the root layout in `app/layout.tsx` must include `<html>` and `<body>`.
- **`page.tsx`** is the UI for a route segment; only one `page.tsx` per folder.
- **Server vs client:** Components are Server Components by default. Add `"use client"` at the top only when needed (hooks, event handlers, browser APIs).
- **Data fetching:** Prefer async Server Components and `fetch` with Next.js caching options. Use Route Handlers (`app/api/.../route.ts`) for API endpoints.
- **Loading & errors:** Use `loading.tsx`, `error.tsx`, and `not-found.tsx` colocated with routes when appropriate.
- **Fonts:** Loaded in `layout.tsx` via `next/font` (Geist variables are applied on `<html>`).

## Tailwind CSS conventions

This project uses **Tailwind CSS v4** (not v3 config style).

- **Entry point:** `@import "tailwindcss";` in `app/globals.css` — no `tailwind.config.js`.
- **Theme tokens:** Defined with `@theme inline { ... }` in CSS. Custom colors/fonts are wired there (e.g. `--color-background`, `--font-sans`).
- **CSS variables:** `:root` holds `--background` and `--foreground`; dark mode overrides via `@media (prefers-color-scheme: dark)`.
- **Usage in JSX:** Standard utility classes (`flex`, `text-zinc-600`, `dark:bg-black`). Semantic tokens like `bg-background` and `text-foreground` map to theme colors.
- **PostCSS:** Configured in `postcss.config.mjs` with `@tailwindcss/postcss` — do not add a legacy `tailwind.config.ts` unless the project adopts one later.
- **Fonts:** Geist sans/mono CSS variables (`--font-geist-sans`, `--font-geist-mono`) are set in `layout.tsx` and referenced in `@theme`.
